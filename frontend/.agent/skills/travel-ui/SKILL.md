# MetroTrip Travel UI

## 디자인 방향

MetroTrip UI는 Wanderlog에서 영감을 받은
`Map-first Travel Planner` 스타일을 따른다.

Wanderlog의 브랜드나 화면을 그대로 복제하지 않고,
다음 구조와 사용 흐름만 참고한다.

- 장소 목록과 지도를 한 화면에서 함께 제공한다.
- 사용자가 현재 선택한 역과 장소를 명확히 표시한다.
- 장소 탐색에서 지도와 목록이 서로 연결되어 동작한다.
- 많은 정보를 카드, 칩, 구역 구분을 통해 정돈한다.
- MetroTrip의 기존 파란색 디자인 토큰을 유지한다.

## 시각적 특징

- 밝고 깨끗한 배경을 사용한다.
- 흰색 또는 옅은 surface 위에 장소 카드를 배치한다.
- 카드 모서리는 기존 `rounded-lg` 또는 `rounded-xl`을 사용한다.
- 그림자는 최소한으로 사용하고 테두리와 배경 차이로 구분한다.
- 파란색 primary는 선택 상태와 주요 행동에만 사용한다.
- 장소 사진은 카드에서 중요한 시각 정보로 사용한다.
- 아이콘은 한 가지 스타일로 통일한다.
- 장식보다 정보 전달과 조작성을 우선한다.

## 화면 구조

### 데스크톱

- 상단에는 주요 화면을 이동하는 내비게이션을 둔다.
- 지도 화면은 장소 목록 패널과 지도의 2단 구조를 사용한다.
- 목록 패널 너비는 전체 화면의 약 30~40%를 넘지 않는다.
- 지도는 항상 가장 넓은 영역을 차지한다.
- 목록 스크롤과 지도 이동은 서로 독립적으로 동작한다.

### 모바일

- 지도를 기본 배경으로 유지한다.
- 장소 목록은 지도 위 바텀시트 또는 접을 수 있는 패널로 제공한다.
- 주요 버튼과 검색 입력은 한 손으로 누르기 쉬운 위치에 둔다.
- 작은 화면에서 데스크톱 사이드바를 그대로 축소하지 않는다.
- 가로 스크롤은 카테고리 칩처럼 필요한 경우에만 사용한다.

## 정보 계층

장소 카드는 다음 순서로 정보를 표시한다.

1. 장소 사진
2. 장소 이름
3. 장소 분류
4. 선택한 역에서의 거리 또는 이동 시간
5. 평점이나 간단한 설명
6. 상세 보기, 길 찾기, 저장 등의 행동

한 카드에 모든 정보를 넣지 않는다.
탐색 단계에서는 사용자가 장소를 비교하는 데 필요한 정보만 표시한다.

## 상호작용

- 장소 카드를 선택하면 해당 지도 마커를 강조한다.
- 지도 마커를 선택하면 해당 장소 카드를 강조한다.
- 선택 상태는 색상뿐 아니라 테두리, 아이콘 또는 텍스트로도 표시한다.
- 필터를 적용하면 현재 적용된 조건을 칩으로 보여준다.
- 긴 작업에는 loading 상태를 표시한다.
- 결과가 없으면 empty 상태와 다음 행동을 제공한다.
- 오류가 발생하면 원인과 재시도 방법을 보여준다.

## MetroTrip 프로젝트 규칙

- `src/index.css`의 색상, 간격, 글꼴, radius 토큰을 우선 사용한다.
- 기존 디자인 토큰을 무시한 임의 색상을 추가하지 않는다.
- `max-w-md`, `w-lg`처럼 기존 spacing 토큰과 충돌하는 클래스는 피한다.
- 필요한 폭은 `max-w-[28rem]`처럼 명시적인 값을 사용할 수 있다.
- `public/` 이미지는 `asset()`을 통해 참조한다.
- GitHub Pages의 `/MetroTrip/` 배포 경로를 유지한다.
- 지도 컴포넌트를 불필요하게 재마운트하지 않는다.
- 요청하지 않은 전면 재설계는 하지 않는다.
- 새 UI 라이브러리는 사용자 승인 없이 추가하지 않는다.

## 작업 절차

1. 수정할 화면의 핵심 사용자 행동을 한 문장으로 정의한다.
2. 관련 컴포넌트와 기존 디자인 토큰을 확인한다.
3. 데스크톱과 모바일 구조를 먼저 결정한다.
4. 정보 계층을 정리한 뒤 스타일을 구현한다.
5. selected, loading, empty, error 상태를 구현하거나 확인한다.
6. 지도와 목록의 연결 동작을 확인한다.
7. 키보드 포커스와 버튼 이름을 확인한다.
8. 린트, 빌드, 브라우저 실행 검증을 수행한다.

## 검증

`frontend/`에서 다음 명령을 실행한다.

- `npm run lint`
- `npm run build`
- `npm run dev`

빌드 성공만으로 UI가 완료됐다고 판단하지 않는다.

브라우저에서 다음을 직접 확인한다.

- 데스크톱 레이아웃
- 모바일 레이아웃
- 스크롤과 오버플로
- 지도 위 요소 겹침
- 장소 및 역 선택 상태
- 화면 전환
- loading, empty, error 상태
