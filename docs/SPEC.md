# MetroTrip — MVP 명세서 (프론트엔드)

> 이 문서가 **MVP 개발의 유일한 기준(Single Source of Truth)** 입니다.
> 여기 없는 기능은 발표 전까지 만들지 않습니다. 범위 변경은 반드시 이 문서를 먼저 수정하고 PR에 링크합니다.

- 최종 수정: 2026-08-04 (경로를 프리뷰에서 실제 동작 기능으로 확장)
- 상태: 확정 (v1.3)
- 담당: 프론트엔드 (우진, 황지성)

---

## 1. 목표

자가용이 없는 사용자가 **지하철 역을 선택하면, 그 역 주변 1km의 가볼 만한 장소가 지도에 표시되는** 웹 앱.
1주일 안에 **발표에서 시연 가능한 MVP**를 만드는 것이 목표입니다.

## 2. MVP 범위 (딱 이것만)

| # | 기능 | 완료 기준 (Definition of Done) |
|---|---|---|
| F1 | 역 선택 | 목록 또는 검색으로 역을 고를 수 있다 |
| F2 | 지도 이동 | 역 선택 시 카카오맵이 그 역 좌표로 중심 이동한다 |
| F3 | 주변 장소 표시 | 반경 1km 내 음식점·카페·관광명소를 마커로 표시한다 |
| F4 | 장소 상세 | 마커 클릭 시 장소명·주소를 인포윈도우로 보여준다 |
| F5 | 반응형 | PC(1920px)/모바일(360px)에서 레이아웃이 깨지지 않는다 |

## 2-1. 발표용 프리뷰 화면 (동작하지 않음)

발표에서 **"다음 단계에는 이런 걸 만듭니다"** 를 보여주기 위한 화면입니다.
F1~F5와 달리 **실제로 동작하지 않아도 됩니다.** 정지된 화면(목업)이면 충분합니다.

| # | 화면 | 완료 기준 |
|---|---|---|
| P1 | 노선도 | 1호선 천안·아산 구간 + 수도권 간략 노선도가 보인다 |
| ~~P2~~ | 경로 | **2-2로 이동** — 실제 동작하는 기능으로 확장됨 (2026-08-04) |
| P3 | 시간표 | 역별 시간표 화면 구성이 보인다 |
| P4 | 마이페이지 | 즐겨찾기·후기·계정 관리 화면 구성이 보인다 |

- 이 화면들은 **"준비중" 표시를 명확히** 해서, 데모 중 실제 기능으로 오해받지 않게 합니다.
- 데이터는 하드코딩해도 됩니다. 단, **거짓 정보로 보이지 않게** 예시임을 화면에 밝힙니다.
  (특히 시간표는 실제 운행 시각 데이터가 없으므로 반드시 예시 표기)
- 설계 근거: `docs/UIUX-설계도.docx` / 관련 논의는 [REQUIREMENTS.md](REQUIREMENTS.md)의 P1·P2 항목.

### 수도권 노선도 — 이미지 + 끌어보는 뷰어

`frontend/public/metro-map.png` 한 장을 지도처럼 **끌어서 움직이고 휠로 확대**해서 봅니다
(`frontend/src/features/line-map/ui/MetroMapPanel.tsx`, 상태는 `features/line-map/hooks/useLineMapViewport.ts`).

- 스크롤바 대신 **잡아 끌기**로 움직입니다. 노선도는 세로로도 길어서
  가로 스크롤바만으로는 아래쪽을 보기 어려웠습니다.
- 처음에는 **가로를 꽉 채우는 배율**로 보여줍니다. 세로까지 다 넣으면
  양옆이 크게 비고 역 이름이 작아집니다.
- 단, 폰 화면 폭(약 310px)에 맞추면 역 이름을 전혀 못 읽으므로
  **최소 900px 폭은 유지**하고 화면 밖으로 나가는 부분은 끌어서 봅니다.
- 확대 한계는 원본 크기(100%)입니다. 그 이상은 뭉개집니다.
- 이미지는 **팔레트 PNG로 압축**해서 넣습니다 (2.8MB → 631KB). 원본을 그대로 올리면 느립니다.
- 이미지 경로는 반드시 `frontend/src/shared/lib/asset.ts`의 `asset()`을 거칩니다.
  GitHub Pages가 `/MetroTrip/` 하위로 서비스되기 때문에 `/metro-map.png`로 적으면 배포본에서 404가 납니다.

> 이전에 직접 그린 SVG 도식 노선도(`metroLines.ts` / `MetroMap.tsx`)가 있었으나,
> 실제 노선도 이미지로 대체하면서 **제거**했습니다. 필요하면 git 이력에서 되살릴 수 있습니다.

## 2-2. 경로 기능 (실제 동작)

> 2026-08-04 범위 확장. 원래 2-1의 프리뷰(P2)였으나 실제 동작하는 기능으로 옮겼습니다.

출발역·도착역을 고르면 **최소 시간 / 최소 환승 두 가지 안을 비교**해서 보여주고,
하나를 확정하면 **경유역마다 내려서 들를 만한 장소**를 추천하는 화면입니다.

| # | 기능 | 완료 기준 |
|---|---|---|
| R1 | 출발·도착역 선택 | 지하철 지도에서 역을 눌러 출발·도착을 고를 수 있다 |
| R2 | 경로 계산 | 최소 시간·최소 환승 두 안을 계산해 나란히 비교한다 |
| R3 | 경로 확정 | 한 안을 고르면 경유역이 순서대로 펼쳐진다 |
| R4 | 경유역 장소 추천 | 경유역에서 그 역 반경 1km 장소를 볼 수 있다 (F3 로직 재사용) |
| R5 | 커버 헤더 | 경로 제목과 요약을 이미지 헤더로 보여준다 |
| R6 | 출발 시각·도착 시각 | 출발 시각을 정하면 경유역마다 도착 예정 시각을 보여준다 |

### 역 선택은 지하철 노선도에서 합니다

카카오·네이버 지하철처럼 **역을 누르면 그 자리에 말풍선**이 뜨고 출발/도착을 고릅니다.
역 위치는 `frontend/src/features/route-plan/lib/schematicLayout.ts`가
**등간격 도식으로 자동 배치**하므로, 노선·역이 늘어나도 좌표를 따로 찍지 않아도 됩니다.
(노선도 화면과 달리 손으로 적은 좌표표를 쓰지 않습니다)

#### 위경도 투영을 쓰지 않는 이유

처음에는 실제 위경도를 투영해 배치했는데 **쓸 수 없었습니다.**
1호선은 남북 145km 로 길어 투영하면 세로로 길쭉해지고, 가로로 넓은 카드에 맞추면
100개 역이 좁은 띠에 몰려 **이웃 역 간격이 1.7px** 까지 좁아졌습니다. 누를 수가 없습니다.

실제 지하철 노선도가 지리를 버리고 등간격으로 그리는 이유가 이것입니다.
등간격으로 바꾸니 간격이 **약 50px** 로 벌어졌습니다.

- 지도는 카드보다 넓습니다. **끌어서** 다른 구간을 봅니다
- 출발·도착역이 바뀌면 그 역으로 **화면이 자동으로 이동**합니다
- 축소하면 라벨이 겹치므로, **겹치는 라벨은 숨깁니다**
  (출발·도착 → 경로 위의 역 순으로 자리를 잡고, 부딪히면 건너뜁니다)
- 확대해도 글자·점은 화면에서 같은 크기로 남고 간격만 벌어집니다

### 설계 관점 — Wanderlog와 다른 점

Wanderlog는 *목적지를 정하고 → 날짜별로 일정을 짜는* 방식입니다.
MetroTrip은 반대로 **이동 경로가 먼저 있고 → 그 경로 위에서 들를 곳을 고릅니다.**
지하철 경로가 곧 일정의 뼈대가 되는 것이 이 서비스의 각도입니다.

### 비교 기준은 "정차역 수"가 아니라 "시간"입니다

카카오지하철이 *"현재 시간 기준으로 가장 빨리 갈 수 있는 경로"* 를 안내하듯,
**도착 시각이 가장 이른 경로**를 최소 시간 안으로 잡습니다.

정차역 수로 비교하면 안 됩니다. 역 사이 소요 시간이 구간마다 다르기 때문에,
시간표가 들어오면 "역을 적게 지나는 경로"와 "빨리 도착하는 경로"가 달라집니다.

### 소요시간은 근사치입니다

실제 소요시간은 열차 시간표(대기시간·환승 대기)가 있어야 계산됩니다.
`train_timetables` 테이블은 있으나 데이터가 아직 없으므로,
지금은 **역당 2분 + 환승 5분** 근사치로 계산하고 화면에 "예상"이라고 명시합니다.
(2-1의 "거짓 정보로 보이지 않게 한다" 원칙과 같은 이유입니다)

데이터가 들어오면 `frontend/src/features/route-plan/api/timetables.ts` 내부만 교체합니다.

### 노선 데이터 — 지금은 껍데기로 둡니다

최소 시간·최소 환승 비교는 **노선이 2개 이상**이어야 의미가 생깁니다.
현재 `stations.json`은 1호선 천안·아산 11개 역뿐이라 환승이 발생하지 않습니다.

전체 노선·역 데이터는 **DB 담당이 API로 제공하기로 협의**되어 있습니다 (2026-08-04).
그전까지는 현재 데이터로 동작하는 껍데기를 만들어 두고,
API가 준비되면 `frontend/src/features/route-plan/api/routes.ts` **내부만 교체**합니다.
탐색 로직은 처음부터 환승을 처리하도록 만들어, 다노선 데이터가 들어와도 그대로 동작합니다.

### 나중에 붙일 것 (지금은 만들지 않음)

경로를 저장·공유하고 커뮤니티로 넓히는 구상입니다. **DB 스키마에 이미 자리가 있습니다.**

| 구상 | 대응되는 기존 설계 |
|---|---|
| 짠 경로를 내 동선으로 저장 | `travel_plans` + `travel_plan_items` |
| 읽기 전용 링크로 공유 | `POST /api/v1/plans/{plan_id}/share-links` |
| "이 경로로 같이 갈 사람" 모집 | `board_posts.plan_id` (모집글에 동선 연계) |
| 참여 신청·수락·거절 | `post_participants` |
| 예산·정산 (Wanderlog 예산 도구) | **없음** — 테이블 신설 필요, DB 담당과 협의 선행 |
| 여행 기간(시작·종료일) | **없음** — `travel_plans`에 날짜 컬럼이 없음 |

## 3. 범위 밖 및 후속 확장

최초 MVP에서는 로그인/회원가입과 백엔드·데이터베이스가 범위 밖이었으나, 2026-08-04 기준 이메일 인증 회원가입·로그인·비밀번호 재설정과 인증 백엔드 API까지 확장 구현했습니다.

소셜로그인, 후기 게시판, 소모임, 즐겨찾기, 여행 동선 계획,
실시간 지하철 위치, 관리자 기능, 친구 추가는 아직 범위 밖입니다.

**노선도·시간표·마이페이지의 실제 동작**(실제 시간표 조회, 전체 노선 데이터,
실제 회원 조회 데이터)은 아직 범위 밖입니다.
위 2-1은 **화면만** 만드는 것이며, 기능 구현은 백엔드 연동 이후입니다.

> **경로 계산은 2026-08-04에 범위 안으로 옮겼습니다.** 2-2를 참고하세요.

→ 전부 발표 이후 작업입니다. 전체 요구사항과 단계별 계획은 [REQUIREMENTS.md](REQUIREMENTS.md) 참고.

## 4. 기술 스택

- React + Vite + TypeScript
- Tailwind CSS v4 + shadcn 패턴 공용 UI + Radix UI Dialog
- 카카오맵 JavaScript SDK + 카카오 로컬(Places) 검색
- 백엔드 없음 — 프론트에서 카카오 API 직접 호출
- 상태관리는 `useState`로 충분. 라이브러리 추가 최소화 (추가 시 PR에서 사유 명시)

## 5. 카카오맵 연동 방법

- SDK는 `index.html`에 script 태그로 로드 (`appkey` = JavaScript 키, `libraries=services`)
- 지도 표시: `kakao.maps.Map`
- 주변 장소 검색: `kakao.maps.services.Places`의 `categorySearch`
  - 카테고리 코드: `FD6`(음식점), `CE7`(카페), `AT4`(관광명소)
  - 옵션: 중심 좌표 = 선택한 역, `radius: 1000`
- 검색 결과를 마커로 표시, 마커 클릭 시 인포윈도우로 장소명/주소 노출

> **지금 상태(발표용)**: 카카오 검색을 매번 호출하지 않고, 탕정역 두 곳
> (써브웨이 아산탕정점 / 매화공원)만 `frontend/src/features/station-map/data/places.json`에 넣어 두고 마커로 찍습니다.
> 좌표·주소는 카카오 로컬 검색으로 실제 값을 확인해 넣었습니다.
> 데이터 형태는 **나중에 백엔드가 내려줄 응답에 맞춰** 잡아 뒀으므로
> (`frontend/src/features/station-map/types.ts`), 연동 시 `frontend/src/features/station-map/api/places.ts` 내부만 fetch로 바꾸면 됩니다.
>
> 참고: 지도에 원래 보이는 상점 아이콘들은 **카카오가 그린 것이라 우리가 클릭 이벤트를
> 붙일 수 없습니다.** 클릭이 되는 건 우리가 직접 찍은 마커뿐입니다.

## 6. 역 데이터

- 백엔드/DB 없이 프론트의 **정적 JSON**으로 둔다 (`frontend/src/shared/data/stations.json`)
- **수도권 전철 1호선** 중에서도 **충남권(천안·아산 구간)** 을 우선 채운다
- 최종 목표는 전체 노선이지만, 프로젝트 기간이 3주이므로 **1호선 → 그중 충남권 구간** 순으로 좁힌다

### 우선 포함할 역 (데모 핵심)

| 역명 | 비고 |
|---|---|
| 탕정역 | 초기 렌더 기준 |
| 아산역 | KTX 천안아산역과 연결된 1호선 역 |
| 배방역 | |
| 온양온천역 | 주변 장소 풍부 — 데모 효과 좋음 |
| 천안역 | 1호선 주요 역 |
| 두정역 / 봉명역 / 쌍용역 / 신창역 | 여유 되면 추가 |

> **주의**: `천안아산역`은 KTX/SRT 전용역이라 1호선 역이 아닙니다.
> 1호선에서 여기에 해당하는 역은 **아산역**(도보 연결)입니다.
> 데이터에는 `아산역`으로 넣되, 검색 편의를 위해 별칭 처리는 추후 고려합니다.

- 데이터 형식:

```ts
type Station = {
  name: string;   // 역명 (예: "서울역")
  lat: number;    // 위도
  lng: number;    // 경도
  line: string;   // 노선 (예: "1호선")
};
```

- 좌표는 실제 값으로 채운다. 초기 렌더 기준 역: **탕정역**
- 노선 확장은 **JSON에 데이터만 추가**하면 되도록 만든다 (코드 수정 없이)

  - `지도`만 실제 기능이고, 나머지 넷은 2-1의 프리뷰 화면
  - 원래 좌측 사이드바였으나, 화면을 넓게 쓰려고 상단으로 옮겼습니다
  - 좁은 화면(`sm` 미만)에서는 글자를 숨기고 아이콘만 남깁니다
- **지도 화면**: 지도가 전체를 채우고, 그 위에 검색창 + 역 목록 카드가 떠 있는 형태
  - 역 클릭 → 지도 중심 이동 + 주변 장소 마커 갱신
- 스타일은 **Stitch 디자인 토큰**(`frontend/src/index.css`의 `@theme`)을 그대로 사용합니다.
  새 화면을 만들 때 색·폰트·간격을 새로 정의하지 말고 기존 토큰을 재사용하세요.

## 8. API 키 관리

- 카카오 JavaScript 키는 `frontend/.env`에 `VITE_KAKAO_MAP_KEY`로 넣고 코드에서 참조
- `frontend/.env`는 `.gitignore`에 포함 (**절대 커밋 금지**)
- 저장소에는 `frontend/.env.example`만 커밋
- 키 발급 방법과 설정법은 루트 [README.md](../README.md)에 기재
